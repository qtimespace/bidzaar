# BRD (Business Requirements Document)

## Проект

### Внутренний модуль "Кошелек пользователя"

### Функциональность

Создание заявки на обмен валюты (Exchange Order)

---

# 1. Контекст проекта

Разрабатывается внутренний модуль цифрового кошелька пользователя. Основная задача кошелька — хранение балансов пользователя в различных валютах и предоставление возможности мгновенного обмена одной валюты на другую.

В рамках данного задания необходимо спроектировать только процесс создания заявки на обмен валют. Исполнение заявки, проведение бухгалтерских операций, взаимодействие с биржей и хранение истории операций находятся за пределами текущего объема работ.

Можно считать, что все необходимые внешние сервисы уже существуют и готовы предоставлять необходимые данные (балансы, курсы валют и создание заявки).

---

# 2. Бизнес-цель

Пользователь должен иметь возможность буквально за несколько секунд обменять одну валюту на другую.

Процесс должен быть максимально понятным и состоять из минимального количества действий.

Основной принцип интерфейса — пользователь всегда должен понимать:

- какую валюту он продает;
- какую валюту покупает;
- какой курс используется;
- сколько средств будет списано;
- сколько средств поступит после обмена;
- какая комиссия удерживается (если она предусмотрена).

Во время оформления заявки система должна минимизировать вероятность пользовательских ошибок.

---

# 3. Основной пользовательский сценарий

Пользователь открывает раздел "Обмен валют".

Система автоматически получает:

- доступные балансы пользователя;
- список поддерживаемых валют;
- актуальные курсы обмена.

После открытия страницы пользователь сразу видит наиболее популярную валютную пару (например RUB → USDT).

Пользователь вводит сумму обмена.

После каждого изменения суммы интерфейс автоматически пересчитывает итоговую сумму получения.

После проверки введенных данных пользователь нажимает кнопку подтверждения.

Система выполняет необходимые проверки.

Если все проверки прошли успешно — создается заявка на обмен.

После успешного создания пользователь получает подтверждение операции.

---

# 4. Функциональные требования

Система должна позволять пользователю:

- просматривать доступные балансы;
- выбирать валюту списания;
- выбирать валюту получения;
- менять валюты местами одной кнопкой;
- вводить сумму вручную;
- быстро выбирать процент от баланса (25%, 50%, 75%, 100%);
- видеть актуальный курс;
- видеть приблизительное время фиксации курса (например "курс действует 15 секунд");
- видеть рассчитанную сумму получения;
- видеть комиссию;
- видеть итоговую сумму;
- подтвердить создание заявки.

После создания заявки пользователь должен получить идентификатор заявки и информацию об успешном создании.

---

# 5. Ограничения

Не допускается создание заявки если:

- сумма меньше минимальной;
- сумма больше доступного баланса;
- выбранные валюты совпадают;
- отсутствует актуальный курс;
- курс устарел;
- сервис обмена недоступен.

---

# 6. Концепция пользовательского интерфейса

## Общая идея

Интерфейс должен быть современным, минималистичным и визуально напоминать лучшие финтех-продукты, такие как Revolut, Wise, Binance, Bybit, Coinbase или Stripe Dashboard.

Основной акцент необходимо сделать на скорости восприятия информации.

Пользователь не должен задумываться, куда нажимать.

Все основные действия должны быть доступны на одном экране без переходов между страницами.

---

## Цветовая палитра

Рекомендуемый стиль — светлая тема.

Фон страницы:

очень светлый серый (#F8F9FB)

Основной цвет интерфейса:

белые карточки

Основной цвет действий:

синий (#2563EB)

Успешные действия:

зеленый (#16A34A)

Ошибки:

красный (#DC2626)

Дополнительный текст:

серый (#6B7280)

Основной текст:

темно-серый (#111827)

Все элементы должны иметь достаточно свободного пространства между собой.

Использовать большие внутренние отступы (16–24 px).

Карточки со слегка скругленными углами (12–16 px).

Легкая тень без сильного контраста.

---

# 7. Структура страницы

Страница должна состоять из одной центральной карточки шириной около 420–480 px.

Внутри карточки элементы располагаются сверху вниз.

## Заголовок

Обмен валют

Подзаголовок:

Выберите валюты и сумму обмена.

---

## Блок баланса

Верхняя часть карточки содержит баланс пользователя.

Например:

Баланс

RUB — 25 450

USDT — 135.27

Можно использовать компактные карточки или простой список.

---

## Блок "Отдаю"

Содержит:

селектор валюты;

поле ввода суммы;

подсказку с доступным балансом.

Справа отображается иконка выбранной валюты.

---

## Кнопка смены валют

Между блоками располагается круглая кнопка со стрелками.

При нажатии:

валюты меняются местами;

суммы автоматически пересчитываются.

Кнопка должна быть визуально выделена.

---

## Блок "Получаю"

Практически идентичен первому.

Сумма рассчитывается автоматически.

Поле недоступно для ручного редактирования.

Под полем отображается пояснение:

"Сумма рассчитана автоматически."

---

## Информационный блок

Под полями располагается компактная информационная карточка.

Она содержит:

Текущий курс

Комиссия

Время действия курса

Итоговая сумма

Все значения располагаются двумя колонками.

---

## Кнопка подтверждения

Находится в нижней части страницы.

Ширина — 100%.

Высота около 48 px.

Цвет — насыщенный синий.

Текст:

"Обменять"

При недоступности операции кнопка становится серой.

---

# 8. Поведение интерфейса

После каждого изменения суммы автоматически выполняется перерасчет.

При смене валют пересчитываются обе суммы.

Если курс обновился во время заполнения формы — отображается компактное предупреждение:

"Курс изменился. Расчет обновлен."

Кнопка подтверждения временно блокируется до принятия пользователем новых условий.

Ошибки отображаются непосредственно возле соответствующего поля.

Не использовать всплывающие окна для обычных ошибок валидации.

---

# 9. Адаптивность

Интерфейс должен одинаково хорошо работать:

- на десктопе;
- планшете;
- мобильном устройстве.

На мобильной версии все блоки располагаются вертикально.

Размер кнопок должен позволять комфортно пользоваться интерфейсом одной рукой.

---

# 10. Архитектурные предположения

Интерфейс взаимодействует со следующими сервисами:

- Wallet Service — предоставляет балансы пользователя.
- Exchange Rate Service — возвращает актуальные курсы.
- Exchange Service — выполняет проверки возможности обмена.
- Order Service — создает заявку на обмен.

Все взаимодействие осуществляется посредством REST API.

---

# 11. Ожидаемый результат работы ИИ

На основании данного документа необходимо подготовить:

1. Концептуальный UX/UI-прототип экрана обмена валют.
2. Высокоуровневый System Design Document (SDD) с описанием компонентов системы и их взаимодействия.
3. Сценарии поведения в формате Gherkin (один Happy Path и минимум два Negative Path).
4. Спецификацию REST API для создания заявки на обмен в формате OpenAPI (YAML или JSON).
5. При необходимости — диаграммы взаимодействия (Sequence Diagram, Component Diagram или C4 Level 2), если это помогает лучше объяснить архитектуру решения.
