# Портал документации Exchange Order

Два адреса, как просил заказчик: **вики** с документацией проекта и **Swagger UI**
со спецификациями API.

| Что | Адрес в dev-режиме | Адрес в собранном портале |
|-----|--------------------|----------------------------|
| Вики (MkDocs Material) | <http://127.0.0.1:8100/> | <http://127.0.0.1:8080/> |
| Swagger UI | <http://127.0.0.1:8101/> | <http://127.0.0.1:8080/swagger/> |

Порт прототипа (`5173`) не затрагивается.

---

## Запуск

Всё выполняется из каталога `portal/`, PowerShell:

```powershell
cd D:\Project\bidzaar\portal
npm install          # один раз: swagger-ui-dist + mermaid для офлайн-режима
```

### Режим разработки — два сервера, два порта

```powershell
npm run wiki         # http://127.0.0.1:8100/   — вики, с автоперезагрузкой
npm run api          # http://127.0.0.1:8101/   — Swagger UI
```

Каждая команда занимает свой терминал.

### Сборка и раздача статики

```powershell
npm run build        # → portal/dist/  (mkdocs build --strict)
npm run serve        # http://127.0.0.1:8080/  и  http://127.0.0.1:8080/swagger/
```

В собранном виде это одно статическое дерево: вики в корне, Swagger UI в
`swagger/`. Все ссылки между ними относительные, поэтому портал переносится
под любой домен и любой префикс пути — nginx/`Caddy`/GitLab Pages, без правок.

### Остальные команды

```powershell
npm run sync         # только подготовка генерируемых файлов
npm run clean        # удалить dist/ и всё генерируемое
```

## Как решён вопрос дублирования контента

**Markdown-документы не копируются вообще.** В `wiki/docs/` лежат только
страницы-обёртки размером в одну строку:

```markdown
--8<-- "docs/SDD.md"
```

`pymdownx.snippets` с `base_path`, указывающим на корень репозитория
(`d:\Project\bidzaar`), подставляет исходный файл в момент сборки. Второй копии
не существует физически, поэтому расходиться нечему — правка `docs/SDD.md`
попадает в вики при следующей сборке, а забыть «синхронизировать» невозможно.

Почему не `docs_dir`, указывающий прямо на `d:\Project\bidzaar\docs`:
тогда пришлось бы класть служебные страницы портала (`index.md`, `run.md`,
CSS, Swagger UI) внутрь каталога документов проекта и мусорить в чужой зоне,
а нав-структура была бы жёстко привязана к расположению файлов на диске.
Почему не симлинки: на Windows требуют прав администратора или Developer Mode.
Почему не копирование markdown скриптом: именно оно и создаёт вторую копию,
которая живёт своей жизнью, если кто-то отредактирует её напрямую.

**Копируется только то, что должно попасть в сайт файлом, а не текстом** —
этим занимается `tools/sync.py`, встроенный в каждую команду запуска и сборки:

| Что | Куда | Зачем |
|-----|------|-------|
| `docs/api/*.yaml` (10 шт.) | `api/specs/` | их читает Swagger UI по HTTP |
| `docs/features/exchange-order.feature` | `wiki/docs/features/` | ссылка «скачать исходник» и ссылка из `features/README.md` |
| `node_modules/swagger-ui-dist/*` | `api/vendor/` | Swagger UI без интернета |
| `node_modules/mermaid/dist/mermaid.min.js` | `wiki/docs/assets/javascripts/` | диаграммы без интернета |
| `api/**` | `wiki/docs/swagger/` | чтобы собранный портал был одним статическим деревом |

Всё перечисленное — генерируемое и указано в `.gitignore`.

## Mermaid

13 диаграмм (12 в SDD, 1 в UX-спеке) отрисовываются через `pymdownx.superfences`
с кастомным fence — в собранном HTML это `<pre class="mermaid">`, который
подхватывает Material.

Material по умолчанию тянет Mermaid с `unpkg.com`, но делает это **только если
`window.mermaid` не определён**. `tools/sync.py` кладёт локальную копию
`mermaid.min.js` (3,4 МБ) в `extra_javascript`, поэтому обращения к CDN нет.
Если `node_modules/mermaid` отсутствует, скрипт кладёт на его место пустую
заглушку и печатает предупреждение — диаграммы продолжат работать, но уже
через интернет.

## Swagger UI

`api/index.html` — статическая страница с переключателем спецификаций
(`urls` + `urls.primaryName`): основной контракт `exchange-orders.openapi.yaml`
и девять контрактов внешних сервисов S1…S9 с человекочитаемыми названиями.

Swagger UI подключается **локально** из `api/vendor/` (пакет `swagger-ui-dist@5`
установлен в `portal/node_modules`). Если каталога `vendor/` нет — страница
показывает жёлтую плашку и грузит Swagger UI с `unpkg.com`; это **требует
интернета**, и для офлайна нужно выполнить `npm install` + `npm run sync`.

## Структура

```
portal/
├─ package.json            скрипты wiki / api / build / serve / sync / clean
├─ tools/sync.py           подготовка генерируемых файлов (см. выше)
├─ wiki/
│  ├─ mkdocs.yml           MkDocs Material: палитра #2563EB, ru-поиск, mermaid
│  └─ docs/
│     ├─ index.md          Обзор — единственная авторская страница-витрина
│     ├─ run.md            как запустить портал, прототип, проверку документов
│     ├─ 00-canonical-model.md, sdd.md, ux-ui-spec.md, BRD.md, promtlog.md
│     ├─ brief/*.md        четыре брифа + продуктовый контекст
│     ├─ api/index.md      обзор API + кнопка в Swagger UI
│     ├─ api/integrations.md
│     ├─ features/         index.md + страница с .feature под подсветкой gherkin
│     └─ assets/           extra.css (палитра), logo.svg, favicon.svg
├─ api/
│  ├─ index.html           Swagger UI + переключатель 10 спецификаций
│  ├─ specs/               ← генерируется
│  └─ vendor/              ← генерируется
└─ dist/                   ← генерируется (npm run build)
```

Имена файлов-обёрток `00-canonical-model.md`, `BRD.md` и расположение
`features/` выбраны не случайно: исходные документы ссылаются друг на друга
относительными путями (`./00-canonical-model.md`, `../BRD.md`,
`./exchange-order.feature`), и такая раскладка делает эти ссылки рабочими
без переписывания исходников. Сборка проходит с `--strict`, то есть любая
битая ссылка роняет билд.
